# Подготовка релиза

## Перед сборкой

1. Зафиксируйте изменения и проверьте состав коммита: без личных данных, ключей, логов и каталогов сборки.
2. Проверьте версию и номер сборки в Xcode-проекте и `scripts/generate_project.py`.
3. Обновите описание выпуска в `docs/releases/`, требования и ограничения в README.
4. Соберите приложение и тестовые исходники. Отдельно укажите, какие проверки действительно запускались.

## Сборка пакета

```sh
python3 scripts/build_release.py
```

Скрипт собирает Release для `arm64` и `x86_64`, проверяет локализованные имена и иконку, подпись и разрешения, упаковывает DMG, проверяет его контрольную сумму и содержимое после монтирования только для чтения. Тесты и приложение не запускаются.

В образ и в ресурсы приложения включаются `LICENSE` и `NOTICE`. Демонстрационные данные не входят в Release. Результаты находятся в `dist/`.

Текущая подпись — ad-hoc; это не Developer ID и не нотариализация Apple. Не обещайте отсутствие предупреждений Gatekeeper. Для подписанных публичных выпусков потребуется отдельный процесс с сертификатами Apple; ключи нельзя хранить в репозитории.

## GitHub Release

В [Releases](https://github.com/Alex-De-Vep/tasks-macos/releases) создайте выпуск с тегом версии, например `v0.1.42`, на проверенном коммите. Для текущего этапа используйте **pre-release**. Заголовок — «Задачи 0.1.42 / Tasks 0.1.42».

Вложите только:

- `Tasks-0.1.42-macOS-universal.dmg`;
- `Tasks-0.1.42-macOS-universal.dmg.sha256`.

Текст выпуска берите из соответствующего файла в `docs/releases/`. Исходные архивы GitHub создаст из тега; бинарные сборки не следует коммитить в Git. Не заменяйте опубликованный тег другим коммитом — для исправлений выпускайте новую версию.

## Проверка загрузки

После скачивания DMG и файла контрольной суммы в одну папку:

```sh
shasum -a 256 -c Tasks-0.1.42-macOS-universal.dmg.sha256
```

Контрольная сумма проверяет целостность файла, но не заменяет подпись Developer ID или нотариализацию.
